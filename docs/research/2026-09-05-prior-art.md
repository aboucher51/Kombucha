# Prior art: agent-driven Godot development loops

Survey date: 2026-09-05. Question: has anyone else built the loop the
Template repo implements (Claude edits → headless GUT → headless boot →
scripted scenario + screenshots → Claude reads results), and what did they
learn that we have not?

Short answer: yes, the same loop has been built independently at least six
times in the last year, in three shapes. None of them is a drop-in
replacement for ours, but several converge on the same design rules the
Template already encodes, and a handful have pieces worth stealing.

## Baseline: what the Template does today

- `tools/test.sh` — GUT 9.7.1 via `gut_cmdln.gd`, headless, exit code
  passthrough, timeout guard.
- `tools/check.sh` — tests + 8 s headless boot (exit 124 = success, error
  grep, RSS budget) + every scenario through `tools/shoot.sh`.
- `scripts/dev/screenshot_harness.gd` — plain-text scenarios, one command
  per line: `shot`, `wait`, `sleep`, `click <NodeName>`, `assert_visible`,
  `assert_onscreen`, `expect_fail`, project commands via `_project_command`.
  Fails only on `"ERROR: ..."` shaped replies. Needs a real display (WSLg).
- `DebugConsole.execute(line)` is the input-free seam; scenario lines and
  console lines are one vocabulary.
- Conventions in CLAUDE.md: stable node names for code-built UI, redirectable
  save paths, `_sandbox()` for global state between batched scenarios.

## The landscape, in three shapes

### A. Editor-bridge MCP servers (editor must be open)

The largest group. An addon inside the running editor talks to a sidecar
(Node or Python) that speaks MCP to Claude. They give the agent the editor's
scene tree, undo-aware mutations, play-mode control, screenshots and input
injection.

| Project | Notable |
|---|---|
| satelliteoflove/godot-mcp | Deterministic playtesting: freezes the game clock at start, `godot_game_time` steps exact slices or steps until a condition holds, inputs ride inside the window. `godot_runtime_state` gives JSON digests, watch windows and signal timelines so screenshots are taken only "when it's actually worth the tokens". `godot_exec` runs GDScript in the live game for scenario setup. 21 tools / 86 actions. Explicitly does not start Godot for you. |
| mkdevkit/godot-mcp | QA tools: `run_test_scenario`, `assert_node_state`, `assert_screen_text`, `run_stress_test`, `get_test_report`. Screenshot diff. |
| hybridindie/godot-mcp | 180 tools in 29 gated toolsets; safety classes (`read_only`/`mutating`/`destructive`/`runtime`), `dry_run`, `confirm=True`. Runtime probe autoload for input sim and profiling. GUT integration, per-pixel screenshot compare. Structured JSON errors with recovery hints. |
| beckettlab/beckett-godot-mcp | Zero sidecar: the MCP server is a GDScript TCPServer polled on the editor thread. Validate-before-write: `write_script` refuses non-parsing GDScript; C# gets `dotnet build` diagnostics as file:line:col. Paid tier adds `click_button_by_text`, `click_world`, `assert_node_state`, `assert_screen_text`, `test_run`. |
| 3ddelano/gdai-mcp-plugin-godot, IvanMurzak/Godot-MCP, youichi-uda/godot-mcp-pro (162 tools, paid), "Agent Tools" (asset 5070, 70 tools) | Same shape. Agent Tools routes every write through PackedScene/ResourceSaver/ResourceUID rather than editing `.tscn` text, has parse-checked script patch with auto-rollback, and a `run.scene_headless` tool: scripted input, multi-frame screenshots, JSON state dump, seed, structured errors, plus `test: run` with pass/fail per file+line for GUT/GdUnit4. |
| GDLLM (asset store) | The inverse: the LLM harness lives inside the editor and calls the provider API. Has `run_game`/`suspend_game`, `read_game_ui`, `inspect_game_node`, thrash detection. |

Why it is not our shape: every one of these needs the editor process alive,
which rules them out of CI and of the "one bash command, one exit code"
contract `check.sh` gives Claude. Their value for us is the tool vocabulary
they converged on, not the transport.

### B. CLI-first / headless agent loops (our shape)

| Project | What it is | Closest match to ours |
|---|---|---|
| beremaran/godot-agent-loop (pi.dev, npm) | MCP server, but it *launches* Godot itself and injects an authenticated autoload (`mcp_interaction_server.gd`) via config injection. Loop is stated as "author → validate → run → observe → playtest → verify → refine". Tools: `run_project`, `run_project_tests` (native / GUT / GdUnit4), `verify_project` (bounded runtime run), `verify_export_readiness`, `game_scenario` (composed input sequences), `game_wait_until`, `game_get_errors`, `game_get_ui`, `game_get_scene_tree`, `game_screenshot`, visual regression against baselines with masks. 16 core tools, 40 more behind `godot_catalog`/`godot_call` to keep the default surface inside a token budget. `GODOT_MCP_HEADLESS=true`. Reflection and code execution off by default. | The most complete peer. Same verify-by-bounded-run idea as our exit-124 boot. |
| aigengame/godot-agent (`gda` CLI) | A CLI, not MCP. `--json` emits exactly one result object per command. `scene preflight` boots a scene headless, runs `_ready`, reports `started` plus script errors. `screen frames` captures an N-frame PNG sequence. `gda-daemon` for a long-lived game: tree, state, input, capture, logs, perf. "Refined while building a real game." | Closest in *transport* to ours: shell commands, structured stdout. |
| abagames/headless-godot-skill-kit | An Agent Skill (SKILL.md + tools) for editor-less Godot. Scenes edited via JSON patches applied through Godot APIs, never raw `.tscn`. Pipeline: patch → dry-run validate → apply → 5 s smoke run → logic tests via `--script res://tools/tests/run_tests.gd` → web export. All output to `logs/`. Sets XDG dirs for sandboxing. | Same smoke-run convention. Its lesson: the skill gives rules but the project's AGENTS.md has to orchestrate. |
| vivecuervo7 "Claude Code as a Godot Editor" (blog) | Step runner: each step is a `.gd` taking `(TestContext, Dictionary) -> String`, empty string = pass, error string = fail. A manifest maps aliases and macros (`setup:deck` expands to five steps). Two speeds of step: *fast* (API shortcut, ~2 s) and *UI* (real clicks/drags, 10–15 s), and Claude picks. Live game gets commands through a `.cmd-queue` file polled every 300 ms by an autoload, results plus screenshots in `.cmd-result`. Trace is JSONL for Claude and Markdown for the human. `LiveReload` autoload watches a `.reload` sentinel (could be a PostToolUse hook). Dev-only grid overlay (64/32/16 px) so positions can be named as `MEDIUM (12,5)`. | Nearly identical contract to our harness (`""` vs `"ERROR: ..."`). The fast/UI split and the JSONL trace are the two things we lack. |
| pepwuper "Headless Game Development with Claude Code and Godot" | Devcontainer with Godot headless + export templates, `--dangerously-skip-permissions` inside the container as the security boundary, GitHub Actions to itch.io. Claude built its own tools (story node editor, sprite-sheet cropper). PM persona with explicit "never ask: should I continue?" authority. | Process lessons, not tooling. Never launched the editor after setup. |
| Randroids-Dojo/PlayGodot | "Playwright for Godot." Python client over Godot's RemoteDebugger TCP protocol (port 6007): get/set properties, call methods, input, wait-for-node/signal/condition, screenshot (full or per node), MSE image similarity. Launches with `--headless` by default. **Requires a forked engine** (automation branch). | Closest to an external driver. Its screenshot call is `viewport->get_texture()->get_image()`, which returns null under `--headless` (verified on 4.7), so its headless mode gives blank captures like everyone else. See `2026-09-05-playgodot.md`. |

### C. Skill packs (knowledge, not loops)

godot-prompter (already installed here), Randroids-Dojo/Godot-Claude-Skills,
alexmeckes/godot-claude-skills, vl4dt/godot-skills, PooDoge/godot-mcp-skills.
These tell the agent *how to write Godot*; none of them supply the
verification loop. Randroids' pack pairs with PlayGodot and gdUnit4 and
ships a GitHub Action (install Claude CLI + Godot, run tests, export web).

### D. Adjacent engines

IvanMurzak/Unity-MCP, hatayama/uLoopMCP ("from Editor to Play Mode"),
CoplayDev/unity-mcp, IvanMurzak/Unreal-MCP. Same four-stage loop (intent →
edit → run → evidence). Unity pays a much higher price for headless (domain
reloads, virtual framebuffers). Godot's CLI-first design is repeatedly cited
as the reason this works better here.

## Convergent design rules (things several projects arrived at independently)

These validate what the Template already does. Each appears in at least
three of the projects above.

1. **An input-free seam is mandatory.** Everyone ends up with "call the
   handler directly" fast paths next to "synthesise real input" slow paths.
   We have `DebugConsole.execute` and `click`. vivecuervo7 names the split
   (fast vs UI) and lets the agent choose per step.
2. **Failure must be error-shaped, never a false answer.** Step runner:
   `""` = ok, string = error. Ours: `"ERROR: ..."`. Same rule.
3. **Bounded runs with a timeout are the runtime check.** `verify_project`,
   `scene preflight`, the 5 s smoke run, our exit-124 boot.
4. **Structured output beats grepping logs.** `gda --json` (one object per
   command), JSONL traces, JUnit XML, `get_test_report`. We grep GUT's
   painted summary and rely on exit codes.
5. **Read state before you look at pixels.** satelliteoflove gates
   screenshots behind JSON state readback explicitly for token cost;
   Agent Tools dumps JSON state alongside frames. We have no state dump
   command.
6. **Determinism is a feature you have to build.** Frozen clock and
   step-until-condition (satelliteoflove), seeds (`SHOOT_SEED`, Agent
   Tools), sandboxed XDG dirs (abagames), our `_sandbox()`.
7. **Validate before you write.** Beckett refuses non-parsing scripts;
   Agent Tools patches with rollback. Godot's own `--check-only` does the
   parse check per file but spawns a full engine each time.
8. **Global state leaks between batched runs.** Our `_sandbox()` rule is
   the same lesson as abagames' XDG isolation and PlayGodot's process
   isolation argument.
9. **The project's own instruction file drives the loop.** abagames states
   it outright: the skill supplies rules, AGENTS.md/CLAUDE.md has to say
   when to run them.

## Pieces worth stealing (gaps in our loop)

Ordered by payoff over effort.

1. **JUnit XML from GUT.** `-gjunit_xml_file=<path>` is built into the
   9.x CLI. One flag in `test.sh` and Claude gets failing test names,
   messages and file:line without parsing painted text. Same for the
   scenario harness: emit a JSONL trace (one line per command: command,
   result, elapsed, screenshot path) next to the PNGs.
2. **A state-dump scenario command.** `dump <NodePath> [props...]` returning
   JSON (position, visible, text, custom props). Cheaper than a screenshot
   and assertable. Pair with `assert_prop <NodePath> <prop> <value>`.
3. **`wait_until <condition>` instead of `wait <frames>`.** Poll a console
   expression or node property with a timeout. Removes the most common
   source of flaky scenarios (guessing frame counts).
4. **Fast vs UI variants named explicitly.** We have both (`console` line
   vs `click`) but nothing tells Claude when to pick which. A line in
   CLAUDE.md or a naming convention (`ui:` prefix) would.
5. **Visual regression with baselines and masks.** `shot` already produces
   PNGs; adding `expect_shot <name> [tolerance]` against a checked-in
   baseline, with a mask rect list for timers/particles, turns screenshots
   from evidence Claude reads into assertions CI runs.
6. **Frozen clock + step.** `time freeze`, `step <frames|seconds>`,
   `step_until <cond>` in the harness. Godot supports this via
   `Engine.time_scale = 0` plus manual `process_frame` pumping, or
   `get_tree().paused` with `process_mode` exceptions. Makes input timing
   deterministic.
7. **Parse check before the run.** A `tools/lint.sh` that runs
   `godot4 --headless --check-only -s <file>` on changed scripts (or
   gdtoolkit's `gdlint`) catches the "one typo, 180 s of test run" case.
8. **Long-lived game instance with a command queue.** For iterating on UI
   look, one Godot process that polls a `.cmd-queue` file and hot-reloads
   on a `.reload` sentinel is faster than relaunching per scenario, and the
   file transport needs no sockets or ports. Fits WSLg. Could be wired to a
   PostToolUse hook.
9. **Grid overlay for spatial language.** Dev-only overlay that prints
   cell coordinates so "move it to MEDIUM (12,5)" is unambiguous both ways.
10. **Devcontainer for CI scenarios.** pepwuper and Randroids both run the
    full loop in GitHub Actions. Our scenarios need a display; Xvfb in a
    container would let `check.sh` (not just `--quick`) run in CI.

## What nobody has solved

- **Truly headless screenshots.** `--headless` has no renderer. Every
  project requires a display (WSLg, Xvfb); PlayGodot's engine fork does
  not solve this either, its captures are null under `--headless`. The
  upstream `--offscreen` proposal (godot-proposals #5790, PR #94530) is an
  open draft. Our WSLg dependency is the industry norm.
- **Token cost of vision.** Everyone gates screenshots behind state
  readback or diffs. No one has a principled "when is a pixel worth it"
  rule beyond "read JSON first".
- **Editor-side changes from CI.** `.tscn` edits by hand risk UIDs and
  signal connections (Agent Tools' whole thesis). The CLI-first projects
  either accept that risk or go through JSON patches applied by a Godot
  script. We edit `.tscn` as text; worth a re-import discipline at least.
- **Flakiness.** Only satelliteoflove's frozen-clock design attacks it
  directly. Everyone else has timeouts and retries.

## Recommendation for Microbiome

Keep the shape: shell scripts, one exit code, no editor, no MCP sidecar as
a dependency. That is the only shape that runs identically for Claude, in
CI, and in a fresh scaffold. Spend the iteration budget on the output side
of the loop (items 1–3 above: JUnit XML, JSONL trace, state dump,
wait-until), because that is where the surveyed projects are ahead and
where Claude's read of a result gets cheaper and more reliable. Evaluate
`gda` and `godot-agent-loop` hands-on for vocabulary, not adoption.
